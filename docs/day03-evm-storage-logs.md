# Day 03 - EVM Storage Logs

## 学习目标

- 理解 `EVM（以太坊虚拟机）` 是什么
- 分清 `storage（持久化存储）`、`memory（临时内存）`、`calldata（调用参数）`
- 理解 `event log（事件日志）` 为什么对后端重要

## 核心概念

### 1. EVM

EVM 是链上统一执行智能合约的运行环境。所有节点都要按同样规则执行合约代码，并得到一致结果。

### 2. Storage / Memory / Calldata

- `storage`：长期保存在链上的正式状态
- `memory`：函数执行期的临时数据
- `calldata`：外部传给合约的只读入参

### 3. Event Log

合约执行后可以发出结构化日志。后端通常通过 `RPC（节点远程接口）` 查询这些日志，做充值监听、索引和入账。

## Java 后端映射

- EVM 类似 JVM，但它是全网共同执行而不是单机执行
- storage 类似数据库里的正式业务状态
- event log 类似结构化业务事件，但它是链上执行结果的一部分

## 常见误区

- 误以为链上执行只看状态，不看日志
- 误以为 calldata 就是普通变量
- 忽略 storage 写入成本更高

## 阶段结论

Day 3 的重点是理解：

**Web3 后端很多时候不是自己决定真相，而是在消费链上执行后的真相。**
