# Day 10 - Withdrawal Flow

## 学习目标

- 理解提现链路和充值链路的本质区别
- 理解冻结余额、签名、广播、状态跟踪的关系
- 理解为什么 `txHash` 不等于提现成功

## 核心概念

### 1. 提现本质

平台主动发起链上交易，把资产从平台控制的钱包打到用户地址。

### 2. 典型流程

1. 用户提交提现申请
2. 校验并冻结余额
3. 风控审核
4. 构造交易
5. 调签名能力
6. 广播到链上
7. 跟踪回执和确认数
8. 成功则扣减，失败则解冻

### 3. 核心风险

- 重复打款
- nonce 管理混乱
- 签名边界失控
- 广播成功但执行失败

## Java 后端映射

- 很像审核流 + 资金冻结 + 外部支付发起 + 异步结果跟踪

## 阶段结论

Day 10 的重点是：

**提现系统最重要的不是“发出去”，而是“只正确地发出去一次”。**
