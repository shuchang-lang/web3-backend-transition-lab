# Day 01 - Accounts And Wallets

## 学习目标

- 理解 `EOA（外部账户）` 和 `contract account（合约账户）` 的区别
- 理解 `private key（私钥）`、`public key（公钥）`、`address（地址）` 的关系
- 理解为什么只有 EOA 能主动发起 `transaction（交易）`
- 初步认识 `nonce（交易序号）`

## 核心概念

### 1. EOA

由私钥控制的账户，可以主动签名并发起交易。

### 2. Contract Account

没有私钥，本质上是链上的程序实例，只能在外部交易触发下执行。

### 3. 私钥、公钥、地址

- 私钥是控制权根
- 公钥通常由私钥推导
- 地址再由公钥进一步计算得到

谁掌握私钥，谁就掌握该地址上的资产控制权。

### 4. Nonce

某个 EOA 已发送交易的递增编号，主要用于：

- 保证同一账户的交易顺序
- 防止交易重放

## Java 后端映射

- `EOA` 更像“有签字权的调用主体”
- `contract account` 更像“部署在链上的业务程序”
- `nonce` 很像带顺序约束的请求流水号，但约束更强

## 常见误区

- 误以为合约账户也能像用户一样主动发交易
- 把地址当成普通用户名，而忽略它背后的控制权
- 把 nonce 只当计数器，而忽略顺序和防重放意义

## 阶段结论

Day 1 的重点不是背术语，而是建立“链上身份模型”：

**EOA 负责主动发起动作，合约账户负责被动执行业务逻辑。**
