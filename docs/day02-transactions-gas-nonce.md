# Day 02 - Transactions Gas Nonce

## 学习目标

- 理解一笔链上交易的核心字段
- 理解 `gas（链上执行消耗）` 不是手续费本身
- 理解 `nonce（交易序号）` 如何影响顺序和卡单
- 能区分原生币转账和 `ERC-20（同质化代币标准）` 转账

## 核心概念

### 1. Transaction

链上交易本质上是 EOA 签名后发给网络的状态变更请求。

常见字段包括：

- `from`
- `to`
- `value`
- `data`
- `gas limit`
- `nonce`

### 2. Gas

Gas 是链上执行和状态变更所消耗资源的计量单位。

手续费更接近：

`gas used * gas price`

### 3. Value 与 ERC-20 转账

- 原生币转账主要看 `value`
- ERC-20 转账通常是调用 token 合约，真正的金额信息常在 `data` 和 `event log（事件日志）` 里

### 4. Nonce

同一地址的交易必须按 nonce 顺序执行。前一笔卡住，后一笔也可能被一起卡住。

## Java 后端映射

- 交易像“带签名、要付费、要确认的远程调用”
- gas 像资源预算
- nonce 像带严格顺序约束的请求序号

## 常见误区

- 把 gas 直接等同于手续费
- 误以为 ERC-20 转账一定能从 value 看出来
- 误以为拿到交易哈希就说明业务完成

## 阶段结论

Day 2 的重点是理解：

**链上写操作不只是“调接口”，而是带签名、带成本、带顺序约束的状态更新。**
