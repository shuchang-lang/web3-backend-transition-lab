# Day 09 - Deposit Listener

## 学习目标

- 理解充值监听系统的完整链路
- 理解 `confirmation（确认数）` 的必要性
- 理解 `reorg（链重组）` 对充值入账的影响

## 核心概念

### 1. 充值监听是什么

持续监听链上有没有转账打到平台控制的地址，并把链上结果同步成平台内部账务记录。

### 2. 典型流程

1. 为用户分配充值地址
2. 扫描新区块
3. 解析 `Transfer event`
4. 匹配平台地址
5. 生成待确认充值记录
6. 等确认数达标
7. 正式入账

### 3. 为什么不能一看到转账就入账

因为还要考虑：

- 交易是否成功执行
- 日志是否正确
- 确认数是否足够
- 是否发生链重组

## Java 后端映射

- 很像支付回调 + MQ 消费 + 入账处理
- 核心在幂等、断点续跑、确认数和账实一致

## 阶段结论

Day 9 的重点是：

**链上看到充值，不等于平台账务可以立刻确认。**
